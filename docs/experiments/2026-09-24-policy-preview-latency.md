# Policy preview latency on a fresh origin/main worktree

Date: 2026-09-24T02:23:43-04:00 (2026-09-24T06:23:43+00:00). Host: AMD
Ryzen 7 PRO 8840U, 16 logical CPUs. Compiler: GCC 16.1.1 20260430 through
`build/bin/zcc cc`, C23. Base commit:
`7a7bfe5823ea2b2684f1e45a564fc2a3cb3175ea`.

The real component is `zcode.package.policy.limits`. Its read-only C23 handler
and pure policy table form one declared hot-swap island. The old immutable
module (`sha256:8bb892dd515d4688ac4c82dcbf9890c39f8127936f7b6206856a99ebc2329cb5`)
returned 12 fields. The edited source
(`sha256:4fed304e2b3331baf96a631cd8cd6bb76ebda6753a7b7f7a628d2d5dda435bb1`)
adds `score_to_contributor`, showing 100 for empty facts. The new module
(`sha256:e65839f45c27510912ebd7c77ef12dc67016b8d79cc57ec9b5739ce5d3985d48`)
returned 13 fields with that value when preloaded in a separate CLI process.
`nm -D` showed `vcs_policy_limits_for`, `vcs_policy_tier_for`, and
`vcs_policy_tier_string` defined by the new module, so the island's policy
table is inside the executing artifact. This was process-local preview; no
resident node was restarted or published.

The repeatable preview command is:

```bash
so="$(tools/dev/hotswap-module-fast.sh FILE=engine/controllers/src/policy_native_handlers.c | tail -1)"
ZCL_HOTSWAP_PRELOAD="$PWD/$so" build/bin/z23-dev \
  -datadir="$HOME/.zclassic-c23-dev" -rpcport=18252 \
  zcode package policy limits
```

Timing used Bash's wall clock (`TIMEFORMAT='wall=%3R'`), with a warmed action
plan and unchanged source for lookup samples. The final rebuild sample used
`touch engine/controllers/src/policy_native_handlers.c` before timing
`tools/dev/hotswap-module-fast.sh FILE=engine/controllers/src/policy_native_handlers.c`;
the source bytes were unchanged. The CLI and full Make samples timed the
commands shown above and `make hotswap-try HANDLER=zcode.package.policy.limits
ARGS='zcode package policy limits'` respectively.

| Phase | Before | After |
| --- | ---: | ---: |
| Changed-source module build, wall | 4.792 s | 0.942 s, same-byte save |
| Unchanged module lookup, wall | 4.867, 4.693, 4.952 s | 0.051 s |
| Process-local CLI preview, wall | 0.142, 0.128, 0.135 s | 0.103 s |
| Warm `make hotswap-try`, full wall | not measured | 0.901, 0.886, 0.900 s |

The final fast builder checks the compiler identity on a source miss. Its
same-byte save and CLI preview took 0.942 s and 0.103 s separately; their
1.045 s sum is not a single end-to-end stopwatch sample. Before that final
identity guard, a changed-source module build took 0.280 s. Compile and link
were not separately timed on either successful build. Warm full-command
preview remained below one second. Focused registered proof ran outside the
preview timing:
`make t-fast ONLY=command_input_bounds` passed 1/1 groups with a 21 ms test
body; `make t-fast ONLY=hotswap_policy_module` passed 1/1 groups with a 22 ms
test body. Those body times exclude build and runner startup.

The prior fast builder repeatedly entered the authoritative Make fallback
because `site.css` was 3.3 ms newer than its byte-identical generated header.
The generator preserves the header's mtime when its bytes do not change, so
the timestamp check could not recover. The builder now proves generated CSS
and wallet view bytes once and caches their exact source, generator,
dependency, and header tuples. It refreshes the action plan after script
edits, checks the compiler identity on a rebuild, and compiles the island
unity source with the
authoritative sealed-core section declaration. Changed section closure or
generated bytes still select the authoritative Make path.

Failure recovery was tested by temporarily appending a C `#error` to the
handler. The build failed; after restoring the source, both its SHA-256 and the
retained new module's SHA-256 matched their pre-failure values. Preloading the
retained module still executed and returned `score_to_contributor:100`.
Preloading the original module still returned the old 12-field response.

The documented numeric input example was rejected by the original command
registry before handler dispatch. The C23 input rules now accept nonnegative
integers for `earned_score`, `uploaded_bytes`, and `downloaded_bytes`. A fresh
developer binary returned `score_to_contributor:25` for `earned_score:75`,
resolved a verified-seeder input to its tier, and still rejected `-1`.

The next measured interactive delay is the Make front door: with a cached
module, `make hotswap-try` takes about 0.9 s while direct module lookup and
CLI preview take about 0.05 s and 0.10 s respectively. On an edited source,
the full compiler identity check adds roughly 0.6 s to the fast rebuild. Full
lint, integration proof, and any publication remain separate from process-local
preview.
