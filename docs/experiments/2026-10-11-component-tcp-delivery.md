The revised API preserves strict local three-file reception and adds explicit
public reception of exactly LICENSE, action-preimage.v2, artifact-manifest.v1
and component.so. The receiving caller selects the public content root and
release-blob root independently of incoming bytes. Existing action, artifact,
toolchain, sysroot, harness, fixture, policy and image expectations remain local.
Validated member indices drive both metadata reads and image assembly.

The generic signed release is delivered as an existing bounded blob over the
same actual loopback TCP dispatcher and CAS path. Provider-local release state
is not receiver evidence. The receiver checks bounded blob bytes, canonical
serialization, signature, exact selected package binding, SPDX policy and
bounded root-committed Apache-2.0 license text. It uses the real receiver store's
persistent release acceptance for active-chain, reward-address, namespace,
sequence and equivocation rules. The release's synthetic recipe root is a signed
statement, not verified recipe execution or independent reproduction evidence.
No source-transport wrapper or generic container is introduced.

Release admission requires an explicit local mutation grant, separate from the
caller's execution request. Inert admission accepts OK or DUPLICATE without
image assembly or execution. Public execution re-admits the exact selected
release and requires DUPLICATE before entering the existing sealed HOT_FORK
runner. A first-time OK during execution persists inert admission but refuses
execution. DUPLICATE may still persist/touch store state and catalog generation;
it is not a zero-write claim. An older accepted release below the current
publisher cursor is stale. Opt-in serving remains a separate authority.

The positive owner-zero row is reached through registered
`zcode_swarm_net_shard_01`. It fetches the actual signed release blob and public
package, observes inert OK then DUPLICATE plus fresh sealed execution, and repeats
both fetches under serviced quiescence. Quiescence requires empty queues, no
active downloads and conservation of actual socket-send and receive bytes.
Warm content transfer and CHUNK DATA counters must remain unchanged; control
traffic is allowed. Wrong local policy refuses before assembly, while wrong
object identity reaches the actual runner descriptor refusal. Identity/profile
`admitted` alone is not an execution grant.

Independent controls cover absent, oversized and noncanonical release blobs,
invalid signature, a release for another selected root, license-text mismatch,
missing license at provider admission, unknown extra/wrong-name members at the
receiver, and duplicate-member codec refusal. Wrong chain, reward, namespace,
equivocation and stale releases use valid signatures and actual persistent
receiver acceptance. Re-delivered accepted releases test unchanged cursor/ID
behavior after rejection. The false mutation grant checks public observable
catalog state and is followed by first-time OK admission.

The second row completes the release-blob transfer before corrupting outgoing
component-package chunks. Production P2P framing retains a valid frame checksum;
content verification must observe the engine's typed invalid-chunk result and
receiver service-book offence and no-credit growth for the actual provider key,
with verified-download credit increasing by exactly the received, root-verified
manifest metadata length and one transferred metadata object. No verified
component chunk bytes are permitted. The selected component remains
non-complete with no verified component chunk bytes, assembly, sealed copy or execution, followed
by actual download cancellation. Terminal download state is not required.
Same-host loopback peers retain the production verification exemption; peer-score
accumulation and banning are not qualified by this fixture. It does
not claim specifically image-byte corruption: another component member may be
the first rejected chunk. A deadline or setup failure is not this negative's
successful witness. Other platforms report explicit receiver/TCP unavailability.

Sockets are nonblocking and close-on-exec. The existing platform opener is reused;
Linux accept4 supplies atomic flags absent from the existing accept wrapper.
Only the fixture-created endpoint is accepted. Explicit drains retain cs_send;
transport ticks use monotonic time. Each operation has a ten-second deadline,
content is capped at 4 MiB, total received wire bytes at 8 MiB, and the unchanged
runner deadline is one second. These are bounds, not performance thresholds.
Cleanup closes fixture-owned sockets, queues, stores and directories and shuts
down the disposable runner. The shared assembler owns image/action buffers,
including partial failures; stores retain their own inert CAS objects.

Observations retain selected roots, release ID/acceptance, image SHA256, actual
TCP bytes, fetch time, explicit receiver reads/copies and runner sealing/story
times. Receiver byte counters exclude the runner's additional copy/hash, kernel
page faults and unspecified computation. No speed ratio or zero-total-work claim
is established. The actual Clang pure-module fixture and story-object digests do
not turn synthetic toolchain/input roots into observed LINK provenance.
Installation, HOT_SHADOW, authenticated production peers, cross-machine delivery,
BUILD receipt reuse, independent reproduction and deployment remain unqualified.
