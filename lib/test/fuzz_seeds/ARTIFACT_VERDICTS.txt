# ARTIFACT_VERDICTS.txt — what we decided about every saved fuzz finding.
#
# On 2026-07-14 a fuzzer found that a five-byte script from any peer hangs the
# node forever. The bytes were committed to this corpus as
# script/timeout-689f73ac89dc1264744711de8383742b90c892b0.bin and then read by
# nobody for two weeks. Three separate mechanisms had already replayed it and
# already gone red; none of them could fail a build, so the finding was a file.
#
# This ledger is what makes that impossible to repeat. Every artifact-prefixed
# seed in this corpus MUST have exactly one line here, and
# tools/lint/check_fuzz_artifact_replay.sh compares every line against what the
# artifact actually does today. There is no directory-wide exemption: an
# artifact nobody has triaged fails the build, and so does a line that has
# stopped being true.
#
# The six prefixes that make a file an artifact are the six libFuzzer writes:
#
#   crash-  timeout-  oom-  leak-  slow-unit-  minimized-from-
#
# `minimized-from-` is what `-minimize_crash=1` produces, i.e. the file you
# make immediately after finding a crash. It was missing from the gate's regex
# until 2026-07-29, so for a while the normal way to shrink a finding also made
# it invisible. A file named nearly-but-not-quite like one of the six
# (CRASH-..., crash_..., hang-...) is now refused by name rather than filed as
# an ordinary seed.
#
#   FORMAT   <corpus>/<basename>   <verdict>   <YYYY-MM-DD>   # reason
#
#   VERDICTS
#     regression-seed  Audited; does NOT reproduce. Kept so the bug cannot come
#                      back unnoticed. If it ever reproduces again -> FAIL.
#     open             Reproduces. A real, unfixed bug. This verdict does NOT
#                      suppress the failure — it gives the failure a name, a
#                      date and an owner. Still FAILS `make fuzz-replay`. If it
#                      stops reproducing -> FAIL too, so the entry cannot rot;
#                      reclassify it to regression-seed and say why.
#     accepted         Reproduces AND is a known-accepted non-bug. Per-file,
#                      dated, reason mandatory (>= 30 chars) — this is the only
#                      verdict that lets a reproducing artifact pass, and it is
#                      printed by name on EVERY run so it can never go quiet.
#                      If it stops reproducing -> FAIL (reclassify).
#     unaudited        NOT a verdict. Written by an OLD build of
#                      promote_fuzz_artifacts.sh when a new artifact landed,
#                      straight from its filename, and REJECTED by the gate on
#                      sight. Superseded 2026-08-26 — see below — but still
#                      rejected if a hand-edit or an old tree produces one.
#     unreplayable     NOT a verdict. Written by promote_fuzz_artifacts.sh when
#                      it could not get the evidence an artifact's bug class
#                      requires (a missing or unbuildable stock or
#                      pattern-init binary). REJECTED by the gate on sight,
#                      same as unaudited: fail closed, never fail quiet. Build
#                      the missing binary and replay it by hand.
#
# ── ONE CLEAN REPLAY IS NOT EXONERATION (added 2026-08-26) ──────────────────
# A `crash-`/`leak-` artifact — a sanitizer-detected memory-safety finding, as
# opposed to `timeout-`/`oom-`/`slow-unit-`, which are algorithmic hangs
# unaffected by stack contents — can be probabilistic on a clean process. A
# freshly-mapped stack reads back as zero, so one replay against a stock
# binary can come back clean while the exact same bytes crash a long-lived
# process every time. `-ftrivial-auto-var-init=pattern` poisons every
# uninitialized stack slot with a recognizable non-zero pattern instead of
# zero, which turns "probabilistic" into "deterministic" for this bug class —
# see tools/scripts/fuzz_verdict_lib.sh and docs/DEFENSIVE_CODING.md.
#
# So: a `crash-`/`leak-` artifact may be closed `regression-seed` ONLY if the
# reason names EITHER a fix ("fixed by <commit>" / "root cause: ...") OR an
# explicit pattern-init replay that ALSO came back clean ("pattern-init:
# clean (Nx)"). "It replayed clean" with neither is not enough, and
# tools/lint/check_fuzz_artifact_replay.sh now enforces this — a
# regression-seed line missing both is a violation, not a pass.
# `timeout-`/`oom-`/`slow-unit-` kinds are not held to this rule.
#
# THE INCIDENT THIS CLOSES. On 2026-08-26 p2p/crash-e3fef02e...bin was filed
# `regression-seed` with a reason that said, verbatim, the crash was "NOT
# explained, only unreproducible" — a bare non-reproduction claim with no
# pattern-init evidence, on the exact bug class where that claim is
# insufficient. It was the same real, peer-reachable wild-free bug as its
# sibling crash-478b30c0..., which the background fuzz lane caught the same
# day as an ASan heap-buffer-overflow. See the p2p section below for the
# corrected entries and the mechanism.
#
# Verdicts are checked two ways. `make lint` reads this file only (text,
# milliseconds): every artifact has a line, every line has a live fuzz binary
# behind it, no orphans. `make fuzz-replay` actually re-runs all of them and
# fails on any disagreement — that is the one that catches a returning bug.
#
# Adding an artifact: run the reproduce command the gate prints, then write the
# line. "I do not know yet" is spelled `open`, and it is red until someone does.

# ── p2p — 4 artifacts: 3 lane noise, 1 a LIVE remote memory-safety bug ──────
# The three timeout- artifacts are lane noise (audit below, unchanged from
# 2026-07-29). The crash- artifact is NOT: the 2026-08-26 entry that called it
# "replayed clean ... NOT explained, only unreproducible" was WRONG. That
# verdict rested on a single stock replay and a misread of the parse path (the
# claimed "prefilled-tx parse runs out of stream" is false — the 151-byte
# payload parses completely; there is nothing left to run out of). It is a
# real, remotely-triggerable wild-pointer read, currently UNFIXED on this
# branch, and this entry replaces the earlier one rather than patching around
# it — see fuzz_verdict_lib.sh's rule: a crash-/leak- artifact cannot close on
# "it replayed clean" alone.
#
# What the 152 bytes do: byte 0 = 0xf9; 0xf9 % 46 == 19, which selects
# `cmpctblock` from g_inbound_commands[] in tools/fuzz/fuzz_p2p.c. The
# remaining 151 bytes are a complete BIP152 cmpctblock payload — a 140-byte
# block header, a 1-byte solution size of 0, an 8-byte compact-block nonce,
# then a short-txid count of 0 and a prefilled-tx count of 0 — fully consumed.
#
# The bug: total (= num_prefilled + num_short_txids) == 0 takes the first
# hard-failure return in compact_block_reconstruct()
# (lib/net/src/compact_blocks.c:318-319, `LOG_FAIL` — which expands to
# `return false`), and on this branch that return sits ABOVE
# `block_init(out_block)` (line 321). process_cmpctblock()
# (lib/net/src/msg_compact.c:245) then runs `block_free(&out_block)` on
# every reconstruction outcome, which walks whatever pointer and count the
# caller's stack frame happened to hold at that offset — a wild read in
# transaction_free(). Remote and effectively pre-authentication: any
# connected peer, one valid block header plus two zero bytes.
#
# Why a plain replay reads clean: a freshly-mapped stack is zero, so the wild
# walk touches address 0 and (on this harness/build) the process exits
# cleanly — 25/25 stock replays clean, matching the superseded entry's
# finding. Rebuilt with -ftrivial-auto-var-init=pattern (poisons every
# uninitialized stack slot instead of leaving it zero), the SAME bytes crash
# 25/25 times, deterministically:
#   AddressSanitizer: SEGV on unknown address ... READ memory access
#   #0 transaction_free  lib/primitives/src/transaction.c:56
#   #1 block_free        lib/primitives/include/primitives/block.h:139
#   #2 process_cmpctblock lib/net/src/msg_compact.c:245
#   #3 msg_process_messages lib/net/src/msgprocessor.c:2213
# rdi/rbx/r12/r14 = 0xaaaaaaaaaaaaaaaa (clang's pattern-init poison byte,
# confirming the read is of the never-initialized out_block.vtx/num_vtx, not
# of anything the fuzz harness itself supplied).
