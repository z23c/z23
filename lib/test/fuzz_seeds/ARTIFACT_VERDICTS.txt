# ARTIFACT_VERDICTS.txt — what we decided about every saved fuzz finding.
#
# On 2026-07-14 a fuzzer found that a five-byte script from any peer hangs the
# node forever. The bytes were committed to this corpus as
# script/timeout-689f73ac89dc1264744711de8383742b90c892b0.bin and then read by
# nobody for two weeks. Three separate mechanisms had already replayed it and
# already gone red; none of them could fail a build, so the finding was a file.
#
# This ledger is what makes that impossible to repeat. Every artifact-prefixed
# seed in this corpus MUST have exactly one line here, and
# tools/lint/check_fuzz_artifact_replay.sh compares every line against what the
# artifact actually does today. There is no directory-wide exemption: an
# artifact nobody has triaged fails the build, and so does a line that has
# stopped being true.
#
# The six prefixes that make a file an artifact are the six libFuzzer writes:
#
#   crash-  timeout-  oom-  leak-  slow-unit-  minimized-from-
#
# `minimized-from-` is what `-minimize_crash=1` produces, i.e. the file you
# make immediately after finding a crash. It was missing from the gate's regex
# until 2026-07-29, so for a while the normal way to shrink a finding also made
# it invisible. A file named nearly-but-not-quite like one of the six
# (CRASH-..., crash_..., hang-...) is now refused by name rather than filed as
# an ordinary seed.
#
#   FORMAT   <corpus>/<basename>   <verdict>   <YYYY-MM-DD>   # reason
#
#   VERDICTS
#     regression-seed  Audited; does NOT reproduce. Kept so the bug cannot come
#                      back unnoticed. If it ever reproduces again -> FAIL.
#     open             Reproduces. A real, unfixed bug. This verdict does NOT
#                      suppress the failure — it gives the failure a name, a
#                      date and an owner. Still FAILS `make fuzz-replay`. If it
#                      stops reproducing -> FAIL too, so the entry cannot rot;
#                      reclassify it to regression-seed and say why.
#     accepted         Reproduces AND is a known-accepted non-bug. Per-file,
#                      dated, reason mandatory (>= 30 chars) — this is the only
#                      verdict that lets a reproducing artifact pass, and it is
#                      printed by name on EVERY run so it can never go quiet.
#                      If it stops reproducing -> FAIL (reclassify).
#     unaudited        NOT a verdict. Written automatically by
#                      promote_fuzz_artifacts.sh when a new artifact lands, and
#                      REJECTED by the gate on sight. It exists so a freshly
#                      promoted finding arrives already failing the build
#                      instead of arriving silently — which is exactly how the
#                      2026-07-14 hang, and eight artifacts that were never
#                      bugs at all, both got into this corpus unexamined.
#
# Verdicts are checked two ways. `make lint` reads this file only (text,
# milliseconds): every artifact has a line, every line has a live fuzz binary
# behind it, no orphans. `make fuzz-replay` actually re-runs all of them and
# fails on any disagreement — that is the one that catches a returning bug.
#
# Adding an artifact: run the reproduce command the gate prints, then write the
# line. "I do not know yet" is spelled `open`, and it is red until someone does.
