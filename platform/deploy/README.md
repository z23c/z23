# `platform/deploy/` — the units and installers this repository ships

This directory is the answer to "what does a running Z23 host consist of, and
how much of it can I get from a clone". Everything here is tracked, reviewed
and reproducible on someone else's machine. Nothing here is generated from a
host's live state.

Read [`../../docs/DEVELOPING.md`](../../docs/DEVELOPING.md) section 0 first if
you are new; this page is about operating a host, not about building.

## What is here

- **Node and lane units.** `zclassic23.service` (the node),
  `zcl23-dev.service` and `zcl23-devfleet@.service` (development lanes),
  `zcl-devd@.service`, `zcl-mind.service`, `zcl-serve.service`.
- **Scheduled maintenance.** `zclassic23-logrotate`, `-worktree-gc`,
  `-test-tmp-clean`, `-bundle-export`, `-build-drift`, `-coverage`, `-fuzz`,
  `-simnet-nightly`, `-replay-canary-*`, `-slo-probe`, `-slo-pager`,
  `-hold-certifier`, `-intervention`, `-tip-agreement`, `-public-smoke`, each
  with its `.service` and `.timer`.
- **Landing.** `z23-land-step.service` / `.timer` drive one beat of the native
  landing service. `zclassic23-lander.service` is the older shell lander and is
  a different thing — its own header says so.
- **Agents.** `zcl-agent-worker@.service` and `zcl-agent-receive@.service`, the
  instanced pair. The instance name is the box's own agent identity.
- **Installers.** `setup.sh`, `provision-z23-build-host.sh`,
  `install-host-watchdog.sh`, `migrate-role-names.sh`, and the bundle and
  cutover scripts. Subdirectories `fleet-gateway/`, `devfleet/`, `examples/`,
  `systemd/` and `system/` carry their own READMEs or headers.
- **[`devbuild`](devbuild)** — a reference copy, not an installed program. See
  its header.
- **[`devbuild-broker`](devbuild-broker)** — a staged Linux replacement for the
  host scheduler. It admits two ordinary heavy lanes, reserves an additional
  interactive lane, and orders release proof ahead of ordinary queued work.
  Explicit `--class normal` jobs request 8 GiB each. Unclassified calls retain
  the legacy 24 GiB per-project memory ceiling, with unused CPU available
  through the existing collective development slice. CPU, RAM, and I/O
  admission tokens are bounded under that slice;
  [`test-devbuild-broker.sh`](test-devbuild-broker.sh) exercises concurrent
  admission, queue order, and the old-wrapper drain gate with short isolated
  scopes. It is not installed by the repository. During a host cutover, write
  the previous script's device/inode and the current nanosecond timestamp to
  `~/.local/state/development/broker-v1/legacy-inode` before atomically
  replacing `~/.local/bin/devbuild`. The new script refuses admission while any
  interpreter still has that old inode open. Keep the prior script as a private
  rollback copy. The existing `devbuild` mirror describes the pre-cutover
  contract until installation and qualification complete.

## What a tracked unit has to earn

A unit belongs in this directory when all four hold. `z23-land-step.service`
is the worked example; read it before adding one.

1. **It runs something a clone has.** The `ExecStart` names a binary this
   repository builds, or a script this repository tracks. A unit pointing at
   an untracked file is not shippable, however good the unit is.
2. **Its header says WHY, not what.** Every non-obvious directive carries the
   measurement or the failure that put it there. `Restart=always` beside a
   loop that exits cleanly, a memory ceiling, a `TimeoutStartSec` — each of
   those is a decision, and the file is where the reason lives.
3. **It carries no operator-private value.** No ssh target, no key or key
   path, no onion address, no personal absolute path, no chosen peer IP.
   Parameterise with `%h` and `%i`, or template it into `examples/`.
4. **It is registered where a reader will look** — this page, plus the
   subsystem page that owns the behavior.

## The host-only units, and why each one stays out

Counted on the maintainer's host on 2026-09-19: 71 installed `z23*`/`zcl*`
user units, of which 40 are tracked here. Of the 31 that are not, two are
generated by a tracked installer and 29 are genuinely host-local. This is that
list, so the next person comparing `ls ~/.config/systemd/user/` against
`git ls-files platform/deploy/` does not have to re-derive it.

| Installed unit | Verdict | Why |
|---|---|---|
| `zclassic23-host-gc.service` / `.timer` | **already shipped, as an installer** | Not a gap. `tools/scripts/install_host_gc.sh` writes both, pointed at the copy it installs beside them; the behavior is `tools/scripts/host_gc.sh` and the page is `docs/HOST_GC.md`. The installed copy of the script has drifted from the tracked one — reinstall rather than edit the copy. |
| `z23-agent-worker.service` | **delete** | Untracked, non-instanced duplicate of the tracked `zcl-agent-worker@.service`. The instanced unit is the one actually running (`zcl-agent-worker@node1-a`); this one is loaded and inactive. It also hardcodes one lane's checkout as its `ExecStart`, which is exactly the "qualified image" mistake the tracked unit's header exists to prevent. |
| `z23-agent-receive.service` | **delete** | Same, against `zcl-agent-receive@.service`. `zcl-agent-receive@node1-a` is the running one. |
| `zcl-e2e-proof.service` | **delete** | its `ExecStart` names `$HOME/zcl-e2e-proof/run-node.sh`; that directory does not exist. Dead unit pointing at a removed file. |
| `zcl-e2e-watch.service` | **delete** | Same directory, same state. |
| `z23-mint-follow.service` | **delete** | A beta6 mint experiment driven from a scratch shell script; loaded, never active, superseded by `z23-beta6mint.service`. |
| `z23-handoff-driver.service` | host-local | Runs `~/.local/state/zclassic23/scratch/northstar/driver/handoff_driver.sh` and pins one lane as its working directory. Out-of-tree shell, see below. |
| `z23-mail-carry.service` | host-local | Its own description calls it an interim pinned-key SSH transport; the script carries ssh targets and key paths. Cannot be committed as-is under rule 3, and the real fix is the native transport, not a template. |
| `z23-lane-watch.service` / `.timer` | host-local | Scratch shell (`northstar/lane_watch.sh`), posts to the host's board. | <!-- doc-path-ok: host scratch paths on the maintainer's box, deliberately not in the tree — that is the point of this table -->
| `z23-board-cpu.service` / `.timer`, `z23-board-sync.service` / `.timer` | host-local | Fleet-board experiment on untracked `~/.local/lib/z23/tools/board.sh`, which carries peer addresses. `board-sync` still contains a commented-out GitHub relay that the owner disabled on 2026-09-03; leave it disabled. |
| `z23-vitals.service` / `.timer` | host-local | Untracked `vitals.sh`, carries host addresses. |
| `z23-xp-daily.service` / `.timer` | host-local | Personal absolute paths into `~/.local/state/zclassic23/scratch/xpdaily` and `experiments/mvp144`. |
| `z23-proc-janitor.service` / `.timer` | host-local, **closest to shippable** | The only one of these whose script carries no private value. It is untracked, so rule 1 blocks it; bring `proc_janitor.sh` in-tree and this unit can follow unchanged. |
| `zcl23-io-guard.service` / `.timer` | host-local, shippable once its script is | Generic and useful — it keeps compile and test disk traffic in the idle class, below the node — but runs untracked `~/.local/bin/zcl23-io-guard.sh`. |
| `zclassic23-db-backup.service` / `.timer` | host-local, shippable once its script is | A clean, well-commented unit; its `~/.local/bin/zclassic23-db-backup` is untracked. |

| `zcl23-dev-loop.service` | host-local | A datadir and RPC port chosen by this host, on top of `zcl23-dev.service`, which is tracked. |
| `zclassicd.service` | host-local, correctly so | Runs the C++ reference client from `~/bin/`, on the operator's own datadir, with a chosen `-addnode` peer. Not a Z23 unit. |
| `zclassicd-oracle.service` | host-local, correctly so | Generated by an out-of-tree renderer from a private env file, and its own header says not to hand-edit it. The consensus-parity oracle is host state, not shipped configuration. |

Drop-in directories (`<unit>.service.d/`) are host-local by construction and
are not counted above. When one has accumulated, reconcile it with the
procedure in [`../../docs/work/canonical-unit-reconciliation.md`](../../docs/work/canonical-unit-reconciliation.md)
rather than reading the directory by eye.

## Out-of-tree shell still in the path

The standing rule is that this project's machinery is C23, not shell. These
are the places where a unit on the maintainer's host still executes a script a
clone does not contain. Listed so the debt is countable; bringing them in is
separate work, not a side errand.

| Script | Driven by | What it would take to bring in-tree |
|---|---|---|
| `~/.local/state/zclassic23/scratch/northstar/driver/handoff_driver.sh` | `z23-handoff-driver.service` | It submits green lanes to the lander, keeps a stepper alive, and ships `main` to the fleet. The lander half is already native (`dev land submit` / `step`, now also driven by the tracked `z23-land-step.timer`), so the remaining shell is lane selection and the fleet ship. Largest item here. |
| `~/.local/lib/z23/tools/mail_carry.sh` | `z23-mail-carry.service` | Interim pinned-key SSH transport between boxes. Replacing it means the native z23 transport, not a port; the script's own header calls it interim. Must not be committed with its ssh targets. |
| `~/.local/lib/z23/tools/board.sh`, `board_gh_relay.sh` | `z23-board-cpu`, `z23-board-sync` | Fleet board post/sync. The relay is already disabled by owner decision. Needs the board to be a native command before the units can be tracked. |
| `~/.local/lib/z23/tools/vitals.sh` | `z23-vitals` | Sample-and-publish. A native `ops` subcommand would retire the unit's `ExecStart` and `ExecStartPost` together. |
| `~/.local/lib/z23/tools/proc_janitor.sh` | `z23-proc-janitor` | Smallest of the set and carries nothing private. Tracking the script is enough; the unit then satisfies every rule above unchanged. |
