# KPI scoreboard floor — lint gate check-kpi-floor.
#
# One `metric value` row per ratcheted metric; `#` starts a comment. The gate
# computes the same metrics as `build/bin/z23 code kpi` over the checkout (no
# node, no code index, nothing written) and fails when a metric is worse than
# its row in its declared direction: below the floor for higher-is-better
# metrics, above it for lower-is-better ones. Equal passes. A metric that
# cannot be measured also fails. `*_pct` values are hundredths of a percent.
#
# TIGHTEN-ONLY. Raise the floor in the same commit that improves the metric.
# Never lower a row to make a regression pass; fix the regression. Rows for
# neutral metrics (capabilities, files_owned, territories, cmd.leaves,
# lint_gates, test_groups) are refused.
#
# Counts of commands, lint gates and test groups are neutral, tracked but never
# floored: consolidation that merges or retires them is an improvement.
#
# Show the rows behind a number: `build/bin/z23 code kpi --group=<cmd|code|docs>`.
