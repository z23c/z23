# malloc_baseline.txt — shrink-only ratchet for check-malloc (z23-lint).
#
# newly scanned 2026-09-06: root list was dead since the tree rename
# (check-malloc used to walk "app" and "tools" — "app" no longer exists —
# so it silently scanned only tools/ and reported OK: no raw allocations
# while ~4,000 files under core/engine/contexts/cognition/platform went
# unscanned). Re-rooted onto the real production tree (core engine contexts
# cognition platform tools); this file pins the debt that visibility
# uncovered. This is CREATING coverage, not raising a baseline: nothing
# here passed the gate before — the gate was not looking.
#
# Each row is "<path>:<symbol>", one row per file that still calls the
# named allocator directly instead of zcl_malloc/zcl_calloc/zcl_realloc (or
# a // raw-alloc-ok marker). Shrink-only: migrate a site onto the checked
# wrapper (or mark it) and delete its row here; a NEW row (not seen before)
# or a STALE row (baselined but the site is gone/fixed) both FAIL the gate.
#
# tools/dev/, tools/lint/ and other developer-only tooling are out of scope
# for this ratchet (raw allocation there was already tolerated); everything
# below is production or package/library C the gate now actually reaches.
